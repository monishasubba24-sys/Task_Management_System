# NON-FUNCTIONAL REQUIREMENTS

Non-functional requirements describe how well the TaskFlow system should work.

| ID | Requirement | Description |
|---|---|---|
| NFR01 | Performance | The system should respond quickly to user requests. |
| NFR02 | Security | User passwords should be securely hashed. |
| NFR03 | Authentication | JWT authentication should protect user access. |
| NFR04 | Usability | The application should be simple and easy to use. |
| NFR05 | Reliability | The system should work correctly without frequent failures. |
| NFR06 | Scalability | The system should support future growth and additional users. |
| NFR07 | Maintainability | The code should be organized into separate modules. |
| NFR08 | Responsiveness | The interface should work on different screen sizes. |
| NFR09 | Data Validation | The system should validate user inputs. |
| NFR10 | Availability | The application should be accessible when required, subject to hosting and network availability. |

## Conclusion

These non-functional requirements ensure that TaskFlow is secure, reliable, responsive, easy to use and maintain.
